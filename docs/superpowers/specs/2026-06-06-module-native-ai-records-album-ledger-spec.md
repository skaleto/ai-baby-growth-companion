# 小宝记模块化 AI 与记录核心化 Spec v0.1

- 创建日期：2026-06-06
- 状态：确认稿，等待实施
- 战略源：`harness/app-development-roadmap.md`
- 调研源：`docs/research-archive/records-album-domestic-app-research-2026-06-06.md`
- 承接上一阶段：`docs/superpowers/specs/2026-06-06-product-simplification-records-trust-spec.md`
- 非范围：AI agent 工具化架构、专家问诊、知识付费、社区、电商。

## 0. 核心判断

小宝记不应该再把 AI 做成一个独立的“聊天中心”。更合适的形态是：

> 记录是首页和主线；AI 是分布在记录、相册、账本等模块里的进阶输入和整理能力。

用户打开 App 时应该先看到“今天宝宝发生了什么、我可以怎么快速记录、刚才记的东西在哪里”，而不是进入一条完整聊天流。AI 的价值要在各个模块里显性化，但不能抢走模块本身的基础能力。

## 1. 产品原则

### 1.1 基础能力必须可手工完成

所有核心模块都要有不依赖 AI 的基础路径：

- 记录：手动维护喂奶、睡眠、便便、体温、成长测量、里程碑。
- 相册：手动上传照片/视频，按天查看，编辑日期和备注。
- 账本：手动新增支出，维护金额、分类、时间、备注。
- 我的：家庭成员、提醒管理、宝宝资料、隐私和订阅信息。

这保证免费用户和不信任 AI 的用户也能完成主任务，也降低 AI 失败时的产品风险。

### 1.2 AI 是模块内的增强入口

AI 不再作为一个底部 Tab 存在，而是以“模块入口”的方式出现：

- 记录页：一句话/语音“记一笔”，把自然语言转成照护记录、成长记录或待确认草稿。
- 相册页：P0 不强化 AI；后续只做低打扰增强，例如自动建议日期、去重、精选封面、生成成长小故事。
- 账本页：图片/小票识别自动记账、消费归类、月度支出摘要。

AI 入口要贴着用户正在做的事情，而不是把用户带离当前模块。

### 1.3 免费与付费按能力层区分

后续商业化不应该按“能不能用 AI”这种粗粒度开关设计，而应该按模块能力分层：

| 层级 | 用户价值 | 建议权限 |
| --- | --- | --- |
| 手动基础记录 | 保证产品可用、可信、长期留存 | 免费 |
| 文本/语音快速记录 | 降低记录负担，是核心差异化入口 | 免费基础额度或轻量 Pro 加成 |
| 图片/视频理解 | 成本高、能力感强，适合付费权益 | Pro |
| 批量整理/跨模块分析 | 有明显效率价值，也有成本 | Pro |
| 导出、家庭协作增强、长期资料包 | 可信工具价值 | 可做 Pro 或家庭版 |

P0 不需要最终定价，但代码和信息架构要支持这个分层。

## 2. 目标信息架构

### 2.1 底部导航

目标底部 Tab：

| Tab | 定位 | AI 形态 |
| --- | --- | --- |
| 记录 | 默认首页，承载今日记录、快速记录、时间线、成长数据、趋势和日历 | 记录页内“记一笔” |
| 相册 | 宝宝照片/视频按天时间流 | P0 无强 AI，P1 可做精选/故事/日期建议 |
| 账本 | 宝宝支出记录 | 手动记账 + Pro 图片识别记账 |
| 我的 | 宝宝资料、家庭成员、提醒管理、隐私、订阅 | 不放模型设置，不做 AI 中心 |

移除：

- 独立 `聊天` Tab。
- 独立 `提醒` Tab。
- 面向用户的模型选择、深度思考、快速模式设置。

### 2.2 聊天历史的处理

聊天能力不删除，历史也不立刻清空，但它不再是主导航：

- 历史对话可以作为“记录助手历史”放在我的页或记录页二级入口。
- P0 可以先不暴露历史入口，只保证数据不丢。
- 记录页里的 AI 回复应转成卡片：已记好、待确认、需要补充、普通问答回复。
- 对用户来说，核心不是“我和 AI 聊了什么”，而是“刚才有没有记到今天”。

## 3. 模块规格

### 3.1 记录模块

记录是默认首页。

基础能力：

- 手动新增喂奶、睡眠、便便、体温、成长测量、里程碑。
- 查看今日摘要、今日时间线、历史日历、趋势。
- 所有记录可编辑、删除、追溯来源。
- 今日统计必须从事件明细聚合，不能只显示最新一笔或旧聚合字段。

AI 增强：

- 记录页提供一个轻量输入条，文案为“记一笔今天的变化...”。
- 支持文本和语音输入，例如“刚才喝了 120ml 母乳”“这周二体重 5.54 公斤，身高 64 厘米”。
- 信息完整时直接写入并展示“已记好”卡片。
- 信息不完整时生成“还差一点”卡片，例如需要确认母乳还是配方奶。
- 成长测量、里程碑等高敏或易错记录优先以待确认草稿呈现。
- AI 普通问答可以在记录页以轻量回复卡展示，但不沉淀成主聊天流。

P0 验收：

- 新用户默认进入记录页。
- 底部没有聊天 Tab。
- 用户仍能从记录页用文字/语音提交记录。
- AI 结果出现在记录页，而不是要求用户进入聊天页查看。
- 今日摘要、时间线、趋势的喂养统计一致。

### 3.2 相册模块

相册的核心不是 AI，而是时间流回看。

基础能力：

- 上传照片/视频。
- 按照片对应日期以天为单位分组，而不是按月分组。
- 每个日期组显示日期、宝宝年龄、照片/视频数量。
- 支持预览、删除、编辑日期和备注。
- 日期来源优先级：`occurredAt`、`date`、`Attachment.createdAt`、上传时间。

AI 增强判断：

- P0 不建议在相册里强行加入 AI。
- P1 可以考虑“低打扰、可关闭”的增强：
  - 自动建议照片日期或修正上传时间。
  - 相似照片去重建议。
  - 自动挑选当天封面。
  - 从照片和记录生成月度成长小故事。
  - 识别可能的里程碑照片，生成待确认里程碑草稿。
- 不建议做实时“相册问 AI”或泛视觉问答入口，容易偏离相册主任务，也会增加成本。

P0 验收：

- 同一天多张照片出现在同一个日期组。
- 跨天照片出现在不同日期组。
- 组标题不再是“2026年6月”，而是具体日期。
- 相册页不出现一个醒目的 AI 中心入口。

### 3.3 账本模块

账本也遵循“手动基础 + AI 增强”的结构。

基础能力：

- 手动新增支出。
- 维护金额、分类、时间、备注、图片附件。
- 查看账本列表、分类统计、月度汇总。

AI 增强：

- Pro 用户可上传小票、截图或商品照片，由 AI 识别金额、商户、品类、时间并生成待确认账本草稿。
- AI 识别后必须让用户确认或编辑，避免误记账。
- 账本分析可以后置，例如“本月奶粉/尿布支出占比”“近 30 天支出变化”。

P0 建议：

- 本轮不重构账本页面。
- 只在信息架构上保留账本 Tab，后续单独做“账本 AI 识别记账”批次。

### 3.4 我的模块

我的页是账号、家庭、隐私和订阅中心，不是 AI 控制中心。

基础能力：

- 宝宝资料。
- 家庭成员。
- 提醒管理。
- 隐私、数据导出、退出登录。
- Pro 状态和权益说明。

不放：

- 模型选择。
- 深度思考开关。
- 快速模式开关。
- “AI 功能中心”。

Pro 权益说明要按模块表达，例如：

- 图片/视频理解。
- 小票识别记账。
- 批量整理和长期资料包。
- 更高的语音/文本智能记录额度。

## 4. 实施拆分

### Batch 1：导航和默认首页

范围：

- 从底部导航移除 `聊天`。
- 默认进入 `记录`。
- 保留聊天相关 state 和历史数据，避免数据丢失。
- 我的页不新增聊天或模型设置入口。

验证：

- `npm run verify:frontend`
- smoke 截图底部 Tab 为 `记录 / 相册 / 账本 / 我的`。
- 新用户或刷新后默认 active tab 为 `records`。

### Batch 2：记录页内 AI 输入条

范围：

- 把当前聊天 composer 能力收敛成记录页“记一笔”输入条。
- 保留文本、语音、发送和必要的图片入口。
- AI 结果以记录页卡片呈现：已记好、待确认、需要补充、普通回复。
- 记录页快捷动作以手动维护为主，不再像聊天快捷问题列表。

验证：

- `npm run verify:frontend`
- 记录页可以输入并触发原有 agent 请求。
- 自动记录结果能在记录页出现。
- 不出现完整聊天页面视觉结构。

### Batch 3：记录页手动维护和层级重排

范围：

- 记录页首屏按“宝宝状态 / 快捷记录 / 今日摘要 / 待确认 / 时间线”组织。
- 成长数据、里程碑、趋势、日历作为记录域内的二级结构。
- 确保手动维护入口明显，AI 只是其中一种输入方式。

验证：

- 手动新增喂奶、成长数据等入口可见。
- 事件统计仍以明细聚合为准。
- smoke 覆盖 390px、430px、768px 无横向溢出。

### Batch 4：相册按天时间流

范围：

- 相册分组从 `YYYY-MM` 改为 `YYYY-MM-DD`。
- 日期标题展示今天/昨天/具体日期、宝宝年龄、数量。
- 预览和编辑日期继续可用。

验证：

- 构造同月不同天照片，显示多个日期组。
- 构造同一天多图，显示同一个日期组。
- 相册主 UI 无强 AI 入口。

### Batch 5：账本 AI 识别记账预留

范围：

- 本轮只确认产品边界，不急着实现。
- 后续做时应独立出账本 Pro 视觉识别 spec。

验证：

- 本轮不影响现有手动账本。
- 未来图片识别能力必须走待确认草稿，而不是直接入账。

## 5. Definition of Done

本 spec 完成后，应满足：

- 底部导航没有 `聊天` 和 `提醒`。
- 默认首页是 `记录`。
- 记录页既能手动维护核心记录，也能通过 AI 快速记录。
- AI 回复和自动记录结果在记录页内完成闭环。
- 相册按天时间流展示，不按月作为主分组。
- 账本继续保留手动记账，图片识别记账作为后续 Pro 增强。
- 我的页只承载家庭、账号、提醒、隐私和订阅，不承载 AI 控制中心。
- 免费/付费分层可以自然映射到“手动基础能力”和“AI/视觉/批量增强能力”。

## 6. 当前推荐决策

推荐本轮先执行 Batch 1-4。

原因：

- 这是用户感知最强的信息架构变化。
- 它能立刻解决“功能太杂、聊天过重”的问题。
- 相册按天时间流是独立、清晰、低风险的体验提升。
- 账本 AI 图片识别适合单独做，因为它涉及 Pro gating、视觉模型、待确认草稿和费用识别准确性，不应该塞进导航重构。
