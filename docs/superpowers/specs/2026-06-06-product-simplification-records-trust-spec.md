## 0. 背景与目标

当前 App 的主线已经明确：记录为基线，陪伴为表达，低焦虑、反疲劳，不做电商、专家、知识付费和开放社区。

这轮用户反馈集中在一个问题：功能已经开始“显得能做很多”，但真实使用路径里，用户只想快速记录、被提醒、回看可信数据。聊天页、记录页、提醒页和我的页的信息架构需要做减法，让主流程更像一个可靠的家庭记录工具，而不是一个堆满 AI 控制项和功能中心的工具箱。

本 spec 的目标：

1. 简化聊天页，让输入、语音、图片和发送成为唯一主流程。
2. 简化记录页，移除今日整理类功能，把成长数据和里程碑前置到记录域。
3. 修正记录统计可信度，确保时间线、今日统计、趋势统计来自同一套事件明细。
4. 取消提醒独立 Tab，把提醒降级为我的页中的一个管理入口，同时保留系统通知能力。
5. 把我的页从“功能集合页”收敛成家庭、账号、隐私和提醒管理页。

## 1. 非目标

本轮明确不做：

- 不新增电商、商品推荐、专家、问诊、知识付费、公开社区。
- 不新增新的 AI 自动整理产品形态。
- 不做复杂成长曲线、同龄对比、百分位展示或焦虑化排名。
- 不重做整体视觉体系，只修当前信息架构和关键移动端布局。
- 不删除提醒能力本身；只移除独立提醒 Tab。
- 不删除成长里程碑能力；只把入口从我的页迁移到记录页。

## 2. 当前问题清单

### 2.1 聊天页过度暴露 AI 控制项

现状：

- 聊天输入区直接展示模型选择。
- 深度思考、低延迟模式也在主输入区以按钮形式出现。
- 用户只是想记录或提问时，会被迫理解模型和模式。
- 顶部快捷按钮里“问 AI”等文案会强化工具感。

问题：

- 和“记录和陪伴”的定位冲突。
- 主输入区按钮过多，移动端容易拥挤。
- 模型/模式是系统实现细节，不应占据日常记录路径，也不需要用户在设置页理解或选择。

### 2.2 记录页信息太繁琐

现状：

- 记录页今日视图含 `DailySummaryView`，包括“小宝今日观察”“整理今天”“重新整理”“这些观察怎么来的”“你可能没注意到”“留意一下”等。
- 我的页还有每日小结提醒设置。
- 成长数据入口虽然在记录页，但排在今日整理和今日信息之后，入口不够直接。

问题：

- “今天整理”相关功能对当前阶段没有必要，增加认知负担。
- 自动整理和整理提醒容易让用户觉得 App 在催记录。
- 成长数据是记录主线的一部分，入口不能藏在较深位置。

### 2.3 今日统计和真实时间线不一致

用户实测：

- 语音聊天里确实记录了 3 次奶量。
- 记录页时间线能看到 3 次记录。
- 今日奶量总和却只显示其中一笔或最新一笔。

代码风险点：

- `careLogs` 里同时存在聚合字段，例如 `milkMl`、`milkTimes`，也存在 `events` 明细。
- 时间线更像是从 `events` 展示，统计和趋势部分有些路径直接读聚合字段。
- 当聚合字段和事件明细不一致时，用户会认为记录丢了。

原则：

> 有事件明细时，奶量、次数、睡眠等统计必须优先从事件明细聚合；聚合字段只作为无事件明细时的兼容 fallback。

### 2.4 趋势页缺少成长信息

现状：

- 记录页趋势主要展示近 7 天奶量、睡眠等照护数据。
- 成长测量已有身高、体重、头围维护能力，但趋势页没有承载这些信息。

问题：

- 成长数据被维护了，却没有在回看场景形成价值。
- 用户会觉得成长记录入口深、反馈弱。

### 2.5 提醒不需要独立 Tab

现状：

- 底部 Tab 包含“提醒”。
- 提醒页是一个完整任务中心，包含待办分组、快捷模板、新建、编辑、延后、完成、删除。

用户判断：

- 用户只需要在特定时间收到待办提醒。
- 不需要每天主动进入一个独立提醒中心。
- 有一个地方能查看和管理提醒即可。

问题：

- 独立 Tab 抬高了提醒的重要性，和记录主线抢空间。
- 底部导航项过多，当前产品显得杂。

### 2.6 发育里程碑放在我的页不合适

现状：

- 我的页顶部有“发育里程碑”入口。
- 里程碑实际与成长事件、成长数据、记录时间线关系更紧。

问题：

- 我的页应该主要承载账号、家庭、隐私和提醒管理。
- 里程碑放在我的页会让成长记录语义割裂。

## 3. 信息架构目标态

### 3.1 底部 Tab

本节为上一阶段已实施目标。2026-06-06 后续方向已改为移除独立聊天 Tab，目标导航以 `docs/superpowers/specs/2026-06-06-module-native-ai-records-album-ledger-spec.md` 为准。

目标底部 Tab：

| Tab | 保留/调整 | 目标定位 |
| --- | --- | --- |
| 聊天 | 保留 | 快速记录、陪伴问答、语音/图片输入 |
| 记录 | 保留 | 今日记录、趋势、日历、成长数据、发育里程碑 |
| 账本 | 暂保留 | 宝宝支出记录，后续可再评估是否弱化 |
| 相册 | 暂保留 | 家庭照片/视频和成长片段 |
| 提醒 | 移除独立 Tab | 迁移到我的页 |
| 我的 | 保留 | 小宝资料、家庭成员、提醒管理、隐私与账号 |

验收：

- 底部导航不再出现“提醒”Tab。
- 现有提醒数据不丢失，系统通知调度不被破坏。
- 直接通过聊天生成提醒、系统通知触发提醒仍可用。

### 3.2 聊天页

目标：

- 聊天页只保留日常输入相关能力：
  - 图片/视频素材按钮。
  - 语音输入按钮。
  - 文本输入框。
  - 发送按钮。
- 模型、深度思考和快速模式都由系统根据输入形态自适应决定，不提供用户手动选择。
- “AI 相关”入口弱化，不在主按钮里强调模型、思考或技术能力。

建议交互：

- 聊天顶部快捷按钮保留低数量常用动作：喂奶、提醒、成长、记账、问 AI。
- 快捷按钮只负责填充输入，不再像功能入口中心。
- 图片/视频能力由 Pro 权限控制：未开通 Pro 时相机按钮置灰但仍可点击，点击后解释这是 Pro 内测能力；开通 Pro 后可直接选择图片/视频。
- 有图片/视频输入时系统走支持视觉理解的豆包链路；纯文本输入时系统走默认 DeepSeek 文本链路。
- 深度思考与快速模式由系统按语境决定，例如简单记录保持快速，长问题或明显分析/建议类问题可自动使用更充分的思考。

验收：

- 聊天 composer 内无模型选择框。
- 聊天 composer 内无深度思考按钮、低延迟按钮。
- 我的页不出现模型选择、深度思考或快速模式设置。
- 未开通 Pro 时相机/素材按钮是置灰态，点击后给出 Pro 能力说明；开通 Pro 后可进入素材选择。
- 移动端 390px 宽度下输入区不横向溢出。

### 3.3 记录页

目标：

- 记录页成为“事实记录和回看”的主场。
- 去掉今日整理类功能。
- 成长数据和发育里程碑在记录页前置。

目标结构：

1. 页头：记录。
2. 分段：今日 / 趋势 / 日历。
3. 今日：
   - 成长数据入口，展示身高、体重、头围最新值，按钮“记录成长数据”。
   - 发育里程碑入口，展示当前月龄、已记录里程碑数、现阶段可观察数。
   - 今日信息，展示成长条数、关键点条数、奶量/睡眠/便便等照护分段。
   - 当天时间线。
4. 趋势：
   - 近 7 天照护趋势：奶量、睡眠等。
   - 成长趋势：身高、体重、头围最新值、上次变化、最近记录日期。
5. 日历：
   - 保留月历和选中日期时间线。

移除：

- 今日整理入口。
- 自动整理按钮。
- 整理中状态。
- 整理提醒。
- “留意一下”“要补一下吗”这类催促性补记弹框。
- 今日交接类模块。

验收：

- 记录页不出现“小宝今日观察”“整理今天”“重新整理”“正在整理已有记录”等文案。
- 我的页不出现“每日小结提醒”设置。
- 成长数据入口在今日视图首屏可见。
- 发育里程碑入口从我的页迁出，在记录页可进入。
- 趋势页包含成长趋势信息。

### 3.4 提醒入口

目标：

- 提醒能力保留，但不作为独立底部 Tab。
- 我的页增加“提醒管理”卡片或列表入口。

我的页提醒管理建议：

- 展示最多 3 条未完成提醒。
- 显示未完成数量。
- 支持进入完整提醒管理子页面。
- 子页面复用现有提醒分组、编辑、完成、延后、删除能力。
- 新建提醒可保留，但不是底部主导航入口。

验收：

- 底部 Tab 无提醒。
- 我的页可查看未完成提醒摘要。
- 我的页可进入提醒管理详情。
- 现有 `openNewReminderEditor`、编辑、完成、延后、删除能力迁移后仍可用。
- 系统本地通知、循环提醒、喂奶间隔提醒不回退。

### 3.5 我的页

目标：

- 我的页只承载“用户/家庭/隐私/账号”。
- 移除发育里程碑入口。
- 增加提醒管理入口。
- 不增加 AI 设置入口或卡片；模型选择和高级模式由系统自适应。
- 移除每日小结提醒。
- Pro 文案不再强调“自动整理、漏项轻提醒”。

目标结构：

1. 小宝资料卡。
2. 家庭成员。
3. 提醒管理。
4. Pro 内测和 AI 用量。
5. 隐私与说明。
6. 退出登录。

验收：

- 我的页不出现发育里程碑入口。
- 我的页有提醒管理入口。
- 我的页不出现模型选择、深度思考、快速模式等 AI 控制项。
- Pro 文案不再出现“今日小结”“自动整理”“漏项轻提醒”作为主卖点。

## 4. 数据可信度规格

### 4.1 CareLog 统计口径

要求：

- 所有面向用户的照护统计优先使用 `CareLog.events`。
- `milkMl`、`milkTimes`、`sleepHours` 等聚合字段只作为兼容 fallback。
- 当 `events` 存在对应类型事件时：
  - 奶量总和 = 所有 `type=milk` 且 `amountMl > 0` 事件的求和。
  - 奶量次数 = 所有有有效 `amountMl` 的 milk 事件数。
  - 睡眠总时长 = 所有 `type=sleep` 且 `durationHours > 0` 事件求和。
  - 睡眠段数 = 有效 sleep 事件数。
  - 便便次数优先按 poop 事件数。
  - 体温展示取最近一次 temperature 事件。

受影响区域：

- 今日信息。
- 当天时间线旁的统计。
- 右侧今日照护面板。
- 近 7 天趋势。
- AI 上下文中传给模型的 selectedCareLog/todayCareLog/recentCareLogs。

验收：

- 构造同一天 3 条 milk events：120ml、20ml、100ml。
- 时间线展示 3 条喝奶记录。
- 今日奶量展示 240ml。
- 今日奶量次数展示 3 次。
- 近 7 天趋势当天奶量也展示 240ml。
- 传给模型的今日上下文也应是 240ml / 3 次，避免模型继续基于旧聚合字段回复。

### 4.2 记录写入一致性

要求：

- 聊天自动写入 careLog 后，事件明细和统计必须同步更新。
- 如果后端或前端已有事件明细，不能只更新聚合字段或只更新时间线。
- 保存后 1-2 秒延迟如果来自云端持久化，应先本地乐观更新，再异步同步云端状态。

验收：

- 用户说“刚才喝了 100ml 奶粉，喝完吐了”后：
  - 自动写入后今日信息立刻更新奶量。
  - 时间线立刻出现本次记录。
  - 如果含吐奶备注，时间线正文能看到备注或标签。
  - 云端同步失败时展示轻量离线状态，不吞掉本地记录。

## 5. 实现拆分建议

确认后建议按 4 个小批次做，每批都有独立验收。

### Batch 1：聊天页减法

范围：

- 从聊天 composer 移除模型选择、深度思考、低延迟按钮。
- 移除我的页 AI 设置卡片或入口。
- 聊天请求侧改为系统自适应路由：图片/视频走豆包，纯文本走 DeepSeek；深度思考/快速模式由系统按输入形态和语境决定。
- 调整相关 CSS 和 smoke 断言。

验证：

- `npm run verify:frontend`
- 静态断言 composer 内不存在 `.model-select`、`.thinking-button`、`.latency-button`。

### Batch 2：记录页去整理化 + 成长前置

范围：

- 移除记录页 `DailySummaryView` 渲染。
- 移除每日小结提醒设置入口。
- 成长数据卡片前置。
- 发育里程碑入口迁入记录页。
- Pro 文案去掉自动整理主卖点。

验证：

- `npm run verify:frontend`
- smoke 覆盖记录页不出现整理相关文案。
- smoke 覆盖成长数据和里程碑入口可见。

### Batch 3：提醒 Tab 迁移到我的页

范围：

- 从 `MOBILE_TABS` 移除 reminders。
- 将提醒页内容改为我的页子视图或 modal/sheet。
- 我的页展示提醒摘要。
- 保留提醒编辑、完成、延后、删除和 native scheduling。

验证：

- `npm run verify:frontend`
- smoke 不再遍历“提醒”底部 Tab。
- smoke 从我的页进入提醒管理并完成现有提醒流程。
- 如 native-risk 未改动 Capacitor 配置，可不跑 native build；如触碰通知调度逻辑，需补 `npm run mobile:sync`。

### Batch 4：统计可信度和成长趋势

范围：

- 抽出 careLog 事件聚合 helper。
- 今日信息、趋势、AI page context 统一使用事件聚合后的 careLog。
- 趋势页增加成长趋势模块。
- 增加回归测试。

验证：

- 新增或扩展 `scripts/test-care-log-helpers.mjs`。
- `npm run test:agent-benchmark`，因为 AI 上下文可能变化。
- `npm run verify:frontend`。

## 7. Definition of Done

本 spec 完成后应满足：

- 用户日常打开聊天页，不会看到模型和模式选择。
- 用户打开我的页，也不会看到模型和模式选择；模型/模式由系统自适应。
- 用户打开记录页，先看到事实记录和成长入口，而不是 AI 整理。
- 用户看到的奶量总和、次数、时间线一致。
- 用户能在趋势页看到成长数据回看。
- 用户不会在底部导航看到提醒 Tab，但能在我的页管理提醒。
- 用户不会在我的页看到发育里程碑入口，成长相关内容归到记录页。
- 移动端 390px、430px、768px smoke 截图无明显重叠、溢出和底部遮挡。
