# Pro 内测白名单与额度策略

更新时间：2026-05-14

## 定位

Pro 内测不是正式会员系统，而是成本受控的付费意愿验证。第一阶段采用手动白名单，目标是在 `¥300-500/月` 成本上限内验证用户是否愿意为高级 AI 照护能力付费。

第一阶段的 Pro 价值锚点是：

> **少输入、少遗漏、自动整理。**

不要把 Pro 直接包装成“多模态 AI”或“家庭交接”。图片、视频、语音、小结、周报和复盘都应服务于同一条提效主线。

## 开通方式

- 家庭提交 Pro 内测申请。
- 运营或开发者人工评估后开通。
- 白名单按家庭维度生效，不按单个账号生效。
- 到期后自动关闭或需要人工续期。

建议第一批白名单家庭数量：`5-10` 个。

## Pro 能力范围

可开放：

- 随手补录。
- 智能漏项追问。
- 每日漏项小结。
- 每日小结。
- 图片理解。
- 视频理解。
- 周报。
- 月报。
- 高级趋势洞察。
- 更智能的相册准入判断。

暂不开放：

- 无限多模态问答。
- 长视频理解。
- 自动后台频繁生成报告。
- 大容量云相册承诺。
- 正式订阅权益。

## 建议额度

### 家庭级默认额度

| 能力 | 默认额度 | 说明 |
| --- | --- | --- |
| 图片理解 | 每家庭每天 `3` 次 | 优先处理宝宝照片、重要凭证和明确用户意图 |
| 视频理解 | 每家庭每周 `1` 次 | 限制时长和文件大小 |
| 每日漏项小结 | 每家庭每天 `1` 次 | 轻提醒型，不做强打扰 |
| 每日小结 | 第一阶段不做次数限制 | 记录 token 明细，先用家庭周/月 token 软告警观察成本 |
| 周报 | 每家庭每周 `1` 次 | 用户主动生成，不自动后台生成 |
| 月报 | 每家庭每月 `1` 次 | 第一阶段不是重点 |
| 高级趋势洞察 | 每家庭每天 `1-2` 次 | 优先用结构化数据，少调模型 |

### Token 预算

每个家庭需要配置 token 上限：

- `weeklyTokenLimit`：周 token 上限。
- `monthlyTokenLimit`：月 token 上限。
- `dailyMultimodalLimit`：每日多模态调用上限。
- `weeklyVideoLimit`：每周视频理解上限。

第一阶段建议从保守值开始：

- 每家庭每周总 token：`100k-200k`。
- 每家庭每月总 token：`400k-800k`。
- 单次图片理解上限：按模型返回 usage 记录，超过预估成本时收紧。
- 单次视频理解上限：必须限制文件大小、时长和调用次数。

实际阈值应根据云端真实 usage 和账单调整。

所有 AI 调用都应记录 usage。建议后续实现一个 `ai_usage_log` 表或等价日志结构。

建议字段：

- `id`
- `family_id`
- `user_id`
- `request_id`
- `provider`
- `model`
- `feature`
- `input_type`
- `input_tokens`
- `output_tokens`
- `total_tokens`
- `created_at`
- `success`
- `error_code`
- `pro_required`
- `quota_counted`

`feature` 建议枚举：

## 超限策略

第一阶段采用“记录 + 软告警”，不直接限制用户：

- 每次 AI 调用记录 token 明细。
- 后台按家庭统计周/月 token。
- 达到阈值后先只在后台或日志中告警。
- 不向用户展示 token、模型或 provider。
- 预留硬限制开关，发现异常消耗后再启用。

如果后续启用硬限制，当家庭达到周/月 token 上限时：

- 不再调用高成本模型。
- 图片/视频理解入口显示额度已用完。
- 文本基础能力可以降级到免费模型或提示稍后再试。
- 明确告诉用户“本周 Pro 试用额度已用完”，不显示技术字段。
- 保留申请扩容或联系内测负责人的入口。

当单次请求可能明显超出成本时：

- 视频过长时直接拒绝或要求裁剪。
- 多张图片一次上传时限制数量。
- 周报/月报重复生成时提示已生成过。

## 成本观察指标

每周需要查看：

- 总 token 消耗。
- 单家庭 token 消耗排行。
- 单用户 token 消耗排行。
- 多模态调用次数。
- 视频调用次数。
- 估算模型成本。
- OSS 存储和流量增长。
- 超限次数。
- 用户是否因额度限制产生明显不满。

## 第一版实现建议

第一阶段可以先做轻量实现：

- 后端保存每次模型返回的 usage。
- 如果模型没有返回 usage，记录请求类型和估算值，并标记为估算。
- 家庭白名单和额度可以先用配置表或简单管理脚本维护。
- 前端只展示自然文案，不暴露 token、provider、model 等技术字段。
- 成本看板可以先用 SQL 查询或脚本输出，不急着做后台管理页面。

## 准出标准

进入正式会员设计前，需要满足：

- 能按家庭统计 AI token 和估算成本。
- 能限制家庭周/月 token 上限。
- 能限制图片/视频/报告类高成本能力次数。
- 超限时用户看到可理解的提示。
- 每周能产出一份成本和使用量简报。
