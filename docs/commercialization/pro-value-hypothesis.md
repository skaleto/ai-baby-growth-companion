# Pro 价值锚点与防遗漏策略

更新时间：2026-05-14

## 核心结论

Pro 的第一付费锚点不应包装成“多模态 AI”或“家庭交接”，而应包装成更贴近照护者日常压力的价值：

> **少输入、少遗漏、自动整理。**

带娃场景下，用户不是不想记录，而是太累、太忙、太碎片化。喂完奶、哄睡、换尿裤、处理哭闹之后，用户可能没有时间立刻打开 App 认真填表。真正值得付费的不是“多一个记录入口”，而是系统能帮用户降低记录成本、减少遗忘，并把零散记录整理成可理解的小结和复盘。

## 付费主线

### A. 少输入

用户希望把信息用最低成本丢进系统：

- 语音说一句。
- 随手打一行字。
- 上传图片或视频。
- 事后补一句“刚才”“半小时前”“下午”“昨天晚上”。

Pro 要让用户感受到：不用填复杂表单，也不用想应该归到哪个分类，AI 会帮忙理解、整理、追问和归档。

### B. 少遗漏

用户真正焦虑的是：我是不是忘了记？是不是漏了重要信息？别人问起来我是不是又要翻聊天记录？

Pro 要帮用户减少这些遗漏：

- 字段不完整时自然追问。
- 支持低摩擦补录。
- 晚上提醒补记录。
- 每日小结前检查可能缺失的信息。
- 把照片、视频、提醒、账本和照护日志串成更完整的当天视图。

### C. 自动整理

用户不是为图表付费，而是为“我不用自己整理”付费。

自动整理应优先体现为：

- 每日小结。
- 每日漏项检查。
- 周照护复盘。
- 趋势变化摘要。
- 值得保存的照片/视频归档。
- 关键提醒和未完成事项汇总。

## 不再作为主锚点的表达

### 家庭交接

“家庭交接”不是第一付费锚点。原因是交接听起来偏低频，一组家庭可能只在月嫂、老人、爸爸妈妈轮换时明显发生一两次。它可以作为副收益存在，但不适合作为 Pro 的主价值表达。

更好的表达是：

- 家人不用反复问今天发生了什么。
- 家庭成员看同一份小结。
- 少翻聊天记录。
- 少重复解释。

这些都应归入“自动整理”和“少沟通”的副收益。

### 多模态 AI

“图片/视频理解”也不应直接作为主锚点。用户不是为模型能力付费，而是为更省事的结果付费。

更好的表达是：

- 拍一下，系统帮你判断是否值得保存。
- 传一段视频，系统帮你整理成长瞬间。
- 图片/视频可以进入当天小结或成长回忆。

## 第一阶段 Pro 内测功能优先级

### 1. 随手补录

支持真实用户表达：

- “刚才喝了 120。”
- “半小时前睡了。”
- “下午拉了臭臭。”
- “昨天晚上醒了三次。”
- “刚刚买尿不湿花了 89。”

要求：

- 能理解相对时间。
- 能识别记录类型。
- 信息足够时自动整理。
- 信息不足时自然追问。
- 不暴露 `milkMl`、`dueAt`、`feedingType` 等技术字段。

### 2. 智能漏项追问

用户输入不完整时，不应该硬记，也不应该丢弃。

示例：

- 用户说“喝奶了”。
- 如果宝宝是混合喂养，系统应问：“这次大概喝了多少？是母乳还是配方奶？”

追问本身就是防遗漏能力的一部分。

### 3. 每日漏项小结

每天固定时间或用户打开 App 时，给出轻量检查：

- 今天还没有睡眠记录。
- 今天喂奶次数比最近几天少。
- 有提醒还没完成。
- 有图片/视频可能值得保存但还没确认。
- 有账本记录缺少分类或金额。

这不是制造焦虑，而是帮疲惫照护者温和补漏。

### 4. 每日小结

每日小结应回答：

- 今天小宝发生了什么？
- 有哪些照护记录？
- 有没有未完成提醒？
- 有没有值得保存的成长瞬间？
- 有没有和最近几天不太一样的变化？

第一阶段采用“轻提醒 + 用户确认生成”：

- 每日小结提醒时间是账号级设置。
- 默认提醒时间为 `21:30`。
- 提醒只引导用户确认生成，不自动后台调用模型。
- 今日小结展示在记录 Tab 的今日页。
- 今日小结按家庭和日期保存最新一版；补录后可重新生成覆盖。
- 今日小结家庭共享，但生成只使用家庭共享数据，不读取账号私有聊天、提醒、待确认、记忆或会话摘要。
- 今日小结使用“事实 + 温和观察”，不做诊断，不给强处置建议。
- 只有照护人可生成或重新生成，所有家庭成员可读。
- 今日小结第一阶段不做次数限制，只记录 token 明细并通过家庭周/月 token 软告警观察成本。

### 5. 周照护复盘

周报应回答：

- 本周喂养、睡眠、提醒、账本、相册有什么变化？
- 哪些事情值得关注？
- 哪些记录可能不完整？
- 下周可以关注什么？

## 防遗漏提醒策略

当前选择：**B. 轻提醒型**

第一阶段不做过于激进的主动推送。推荐策略：

- 每天固定 `1-2` 次轻提醒。
- 优先在晚上提醒补记录和查看小结。
- 不做持续闹钟式打扰。
- 不在误判风险高的场景频繁推送。

### 为什么不选更激进策略

- 保守型只在打开 App 时提示，可能无法减少遗漏。
- 智能型根据历史规律主动提醒有价值，但误判会烦，适合后续再验证。
- 强提醒型会打扰带娃场景，容易造成反感。

## 内测成功标准调整

不再用“有兴趣”作为成功标准。更硬的标准是：

- `5-10` 个家庭中，至少 `3` 个家庭在使用 `7-14` 天后明确表示愿意为 Pro 支付 `¥9.9/月` 或 `¥68/年`。
- 愿意付费的家庭必须能说出一个具体付费原因。
- 每个愿意付费家庭至少实际使用过 `3` 次 Pro 能力。
- 至少 `2` 个家庭愿意接受图片、视频或报告额度限制。
- 如果取消 Pro 能力，用户会明确说这个能力会被想念。

## Pro 文案方向

建议避免：

- “强大的多模态 AI”
- “专业育儿医生”
- “家庭交接神器”
- “全自动判断宝宝健康”

建议使用：

- “少输入、少遗漏、自动整理”
- “喂完奶来不及记，也能之后轻松补上”
- “每天帮你检查可能漏掉的记录”
- “把零散记录整理成当天小结”
- “照片、视频和语音都能帮你整理成回忆和记录”

## 下一步实现提示

后续如果进入实现，应优先做：

- 每日小结入口。
- 每日漏项检查。
- Pro 白名单。
- Token 用量记录。
- 周/月 token 软告警，并预留硬限制。
- 图片/视频额度限制。
- 超限自然提示。
- 极简 Pro 内测申请持久化。
- 家庭级 Pro 权益表。

不要先做完整会员系统、支付、复杂后台或公开 Pro 订阅。
