# 小宝记 5-10 个家庭内测计划

更新时间：2026-05-14

## 目标

本轮内测不是公开增长，也不是正式商业化。目标是在 `5-10` 个真实家庭中验证：

- 家庭是否能连续使用 `7-14` 天。
- 记录、提醒、相册、账本、家庭共享是否能支撑真实照护流程。
- Pro 能力是否真的让用户觉得“少输入、少遗漏、自动整理”。
- 云端服务器、OSS 存储和模型 API 成本是否能控制在 `¥300-500/月`。
- 哪些功能会造成误记录、误提醒、理解错误、媒体加载慢或用户不信任。

## 内测范围

### 推荐家庭构成

- `1-2` 个新生儿家庭：验证高频记录、喂养、睡眠和提醒。
- `1-2` 个多照护人家庭：验证家庭邀请码、角色、共享边界和只读权限。
- `1-2` 个重视照片/视频记录的家庭：验证相册、媒体加载和多模态价值。
- `1-2` 个愿意深度反馈的家庭：验证访谈、问题定位和快速修复流程。

### 发布方式

- Android：使用阿里云 OSS 下载链接或二维码分发 APK。
- iOS：第一阶段只在开发者自己的设备上通过 Xcode 安装；确认价值后再考虑 Apple Developer Program 和 TestFlight。
- Pro：手动白名单，不公开付费，不接真实支付。

## 内测周期

建议分两轮：

- 第 1 轮：`3-5` 个家庭，周期 `7` 天，重点找阻断问题。
- 第 2 轮：`5-10` 个家庭，周期 `14` 天，重点看留存、成本和付费意愿。

## 关键验证问题

### 留存和使用

- 用户是否愿意每天打开。
- 用户是否愿意让其他家庭成员加入。
- 用户是否会持续记录喂养、睡眠、提醒、账本或相册。
- 用户是否能理解哪些数据家庭共享，哪些数据账号私有。

### Agent 质量

- AI 是否误把闲聊、截图、视频、模糊语音当成记录。
- 字段不足时，AI 是否能自然追问，而不是暴露技术字段。
- 提醒、账本、照护日志是否能正确生成结构化结果。
- AI 回复是否会承诺自己没有真正完成的动作。

### Pro 意愿

- 用户是否点击 Pro 内测入口。
- 用户最想试用图片理解、视频理解、周报、月报、趋势洞察中的哪一个。
- 用户是否能接受每日或每周额度。
- 用户对 `¥9.9/月`、`¥68/年` 是否有接受意愿。
- 用户是否能明确说出一个愿意付费的功能。
- 用户是否在实际使用过 Pro 能力后仍愿意付费。

### 成本和稳定性

- 每个家庭的周模型 token 消耗。
- 每个家庭的图片/视频调用次数。
- 每个家庭的 OSS 存储和流量增长。
- 是否存在单个家庭异常消耗成本。
- 是否需要更低的默认额度或更严格的白名单。

## Pro 内测口径

第一阶段 Pro 不是正式会员，而是“限量试用”：

- 手动白名单开通。
- 家庭级额度控制。
- 不承诺无限图片、无限视频、无限 AI 次数。
- 超出额度后明确提示“本周试用额度已用完”，不静默失败。
- 所有高成本能力必须记录用量和估算成本。

## 反馈收集

每个家庭至少做一次访谈，建议问题：

- 你最常用哪个功能？
- 哪个功能让你感觉省心？
- 哪个地方让你不信任 AI？
- 哪个记录或提醒有明显错误？
- 你愿意为哪个能力付费？
- 如果每月 `¥9.9`，你会继续用吗？
- 如果有每日图片/视频额度，你能接受吗？

## 准出标准

本轮内测可以进入下一阶段的条件：

- 至少 `5` 个家庭完成 `7` 天使用。
- 没有高频出现的阻断级登录、同步、上传、提醒失败。
- 至少 `3` 个家庭明确表示愿意为 Pro 支付 `¥9.9/月` 或 `¥68/年`。
- 愿意付费的家庭必须能说出一个具体付费原因，并且至少实际使用过 `3` 次 Pro 能力。
- 至少 `2` 个家庭愿意接受图片、视频或报告额度限制。
- 单家庭月均模型与媒体成本预估可控制在合理范围。
- AI 误记录和误提醒问题有明确整改清单。

## 暂不做

- 不接真实支付。
- 不开放公开注册 Pro。
- 不承诺 iOS TestFlight 外部测试。
- 不做广告、导购或商品画像。
- 不把宝宝数据用于广告推荐。
