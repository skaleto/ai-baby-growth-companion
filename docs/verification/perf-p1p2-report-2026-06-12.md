# P1/P2 架构债性能对比报告(2026-06-12)

本批次还清登记册 P1/P2 清单中可独立落地的四项:**D3(相册窗口化)/ D4(媒体内存生命周期 + IDB 批量预查)/ D5(CSS reset 审计归零)/ D8(核心链路测试补盲)**;D6 维持「随 D1 一起还」(避免 Records/Profile 拆分二次返工),D7 复核触发条件未满足、按既定决策不动。详见登记册各条目。

## 测量方法

- 工具:`scripts/perf-benchmark.mjs`(Playwright + CDP,**6x CPU 节流**模拟中端手机),与 P0 报告同一把尺子
- 数据集:600 相册项(含 54 视频)+ 150 聊天消息 + 60 照护日 + 20 提醒 + 80 账目(mock API,前后完全一致)
- 每版本 3 轮取中位数;同机同尺(M 系芯片,**相对比较有效,绝对值≠真机**)
- **本批对脚本的两处加固**(加固后用同一脚本重测了基线,对比公平):
  1. 相册首开/二开改等 `.album-photo-thumb img`(真实媒体元素)——窗口化后 tile 壳先于媒体出现,等壳会虚高新版成绩;
  2. 新增 `album_mounted_media_first / album_mounted_media_after_scroll`:DOM 中实际挂载的媒体元素数,即 D3 的验收证据。
- 版本:
  - **pre-P1**:本批改造前 HEAD(`22ad291`,即 P0 完成态)
  - **post-P1P2**:D3+D4+D5+D8 完成后

| 指标 | pre-P1 | post-P1P2 | 变化 |
|---|---:|---:|---:|
| 冷启动可交互 boot_ms | 436 | 432 | 持平 |
| **相册首开 album_first_open_ms** | 898 | **463** | **-48%** |
| 相册首开主线程阻塞 blocked_ms | 77 | 64 | -17% |

### 解读

- **相册首开 -48%(898→463ms)**:D3 的直接收益——首挂媒体元素从 600 个降到 16 个(首屏 eager + 观察器补挂),挂载/解码/IDB 查询全部按需化。**真机收益应大于此数**:基准用 1x1 PNG,测不到「600 张真实图片解码 + 600 个并发 IDB 事务」在低端机上的代价(D4 把首挂 IDB 事务从 O(全部) 降到 O(可视窗口) + 首屏单事务批量预查)。
- **挂载媒体数 600→16/33**:D3 验收线「≤ 可视区 ±2 屏」达标;滚动到哪挂到哪、离开即卸,配合 D4 的 objectURL LRU(>200 条 revoke 最旧不在 DOM 的),**长会话浏览大相册的内存从只增不减变为有界**(「500 张 30 分钟内存曲线平稳」待真机长测确认)。
- **返回记录页 -31%(235→163ms)**:离开相册后媒体子树卸载,P0 报告中该指标 +48% 的回归被反向修复(基线 352c016 时代为 165ms,现已回到同水平)。
- **⚠ 滚动阻塞 +9ms / 二开 +12%**:窗口化的代价——快速滚动/重进 Tab 时要做挂载工作(此前全量常驻什么都不用做)。绝对值小(9ms / +38ms),且换来的是上面三项结构性收益;二开 360ms 仍远低于最初基线(352c016)的 790ms。列入观察,真机可感知再调窗口余量(±150%)与 eager 数量。
- **冷启动/输入持平**:符合预期——这两项的瓶颈在 D1(visited-tab 懒渲染 + AlbumScreen memo)已解决,本批不动这条路径;输入剩余成本在聊天列表自身,随 D1 拆 RecordsScreen + D3 聊天列表窗口化处理。

## 本批排查沉淀(写进登记册 D3)

**IntersectionObserver 的 `rootMargin` 在内层滚动容器场景下形同虚设**:`root: null`(视口)时目标 rect 会先被内层 overflow 容器裁剪,再与「视口+margin」求交——相册滚动容器是 `.album-screen`,所以视口外的 tile 永远不相交,预挂载余量从未生效(存量的视频近视口挂载 320px 同样没生效,本批一并修复)。现按「目标最近可滚动祖先」解析 root、按 root 缓存观察器。**今后任何基于 IO 的预挂载/懒挂载必须传对 root。**

## D5 / D8(本基准不覆盖,机制与测试证据)

- **D5 审计归零**:全部裸元素选择器收紧为 `:where(#root, .app-portal) <元素>`(零特异性,级联不变,不再渗透 PhotoSwipe 等第三方容器);portal 到 body 的应用弹层新增 `.app-portal` 标记类规则;pswp 容器内按钮的点按反馈改为容器内显式声明。gesture [I]/[J] + 多视口 smoke 全绿。
- **D8 测试补盲**:新增 `scripts/test-core-flows.mjs`(入 verify:frontend):[N] 聊天发送(composer → mock SSE → 回复进线程 → 消息持久化)、[O] 手动记录(150ml 喂奶 → careLogs 持久化 → 时间线可见)。核心三链路(聊天/记录/相册)自此都有 DOM 级回归。
