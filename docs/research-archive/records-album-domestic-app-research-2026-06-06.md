# 国内母婴 App 育儿记录与相册形态调研

- 日期：2026-06-06
- 范围：国内母婴 App 的育儿记录、成长记录、相册/时间流组织方式
- 目标：为“小宝记”下一轮功能简化提供依据：弱化独立聊天 Tab，把记录作为核心首页；相册从按月聚合改为按天时间流。
- 非范围：AI agent 架构、专家问诊、知识付费、社区、电商。
- 调研边界：本轮基于 App Store、官网等公开描述和当前项目代码结构做产品形态判断；未做竞品真机完整路径拆解。

## 1. 结论

国内母婴产品里，“聊天”不是主导航心智。高频育儿场景更稳定的主线是：

1. 以宝宝为中心的私密记录空间。
2. 喂养、睡眠、便便、身高体重、疫苗/健康等工具型记录。
3. 照片/视频按时间回看，支持家庭成员共同维护。
4. 记录后的统计、成长曲线、日历查找和时间轴回看。

因此，小宝记下一轮应把“聊天”降级为记录页内的输入方式和辅助能力，而不是完整 Tab。底部主导航建议改为：

`记录 / 相册 / 账本 / 我的`

如果继续减法，账本也可以后续再评估是否移入“我的”或“记录”的二级入口；但本轮不建议同时动账本，以免范围过大。

## 2. 竞品观察

### 2.1 亲宝宝

亲宝宝的主心智是“记录成长，科学育儿”。App Store 描述强调“成长记录云空间”，照片、视频可上传，邀请家人加入，安全私密、互动分享；同时提供智能育儿助手、发育测评、早教内容和商城。

启发：

- 核心入口不是“聊天”，而是宝宝私密成长空间。
- 家庭共同维护和相册保存是长期留存抓手。
- 育儿助手是记录之外的辅助层，不应抢主线。

### 2.2 宝宝树孕育

宝宝树孕育覆盖经期、备孕、怀孕到育儿，育儿阶段包含成长记录、身高体重、疫苗接种、成长曲线、宝宝相册、社区、专家课堂等。它也引入“米卡 AI”，但整体仍是综合母婴平台结构。

启发：

- AI 可以存在，但不必作为底部主 Tab。
- “成长记录 + 曲线 + 疫苗/日程 + 宝宝相册”是育儿工具层的主干。
- 小宝记不做专家、社区、电商，应该把复杂度收回到记录和回看。

### 2.3 妈妈网孕育

妈妈网孕育近期版本描述里明确提到：育儿宝宝首页改版、通过语音记录宝宝喂养行为、育儿记录优化、相册支持时间轴和点赞评论、喂养记录发布与查看体验优化。

启发：

- 语音记录应该服务于记录页，而不是塑造成独立聊天产品。
- 记录发布、查看、时间轴回看是同一个闭环。
- 相册“时间轴”比纯分类相册更符合成长记忆心智。

### 2.4 小豆苗

小豆苗以预防接种为核心，同时提供儿童健康功能：身高、体重、生长曲线、喂养、睡眠、便便、用药等记录，生成统计图表；也提供成长提醒、成长相册和发育测评。

启发：

- 疫苗/儿保类能力适合放在记录体系下，而不是独立高频 Tab。
- 记录页需要同时承载“今天发生了什么”和“宝宝阶段性变化”。
- 专业健康内容必须保持免责声明和低风险表达，小宝记只做记录与提醒。

### 2.5 宝宝记（美柚）

宝宝记强调“以宝宝为中心”，支持小视频、照片、文字记录；可设置家人共享、仅邀请亲友可见；全面记录身高体重、疫苗接种、吃喝拉撒睡、长牙换牙、宝宝档案。评论区里用户强烈关心大量照片视频后的查找效率，官方回应支持在宝宝记 Tab 通过日历图标按日期查找记录。

启发：

- “按日期找记录”是成长相册和记录流的关键能力。
- 大量照片/视频会迅速制造查找成本，必须早期设计时间粒度。
- 按天组织比只按月更适合新生儿阶段，因为一天内可能有多条喂养、睡眠、照片和里程碑。

### 2.6 宝宝全记录 / 100 Feed 等记录工具

宝宝全记录强调喂奶、换尿布、睡眠、成长、里程碑、健康等强记录能力，并提供快速模式和详细模式；浏览上支持按天、按项目查看，统计报表按周/月展示。100 Feed 则把心智压到“记录是喂养的小抄，不是作业”，强调进入 App 直接记录、每日目标、数据回顾、夜间友好和小组件。

启发：

- 小宝记的记录页应有“快速记录”和“详细编辑”两层。
- 趋势和统计不应该压在首页第一屏，而应作为记录后的回看层。
- 记录页第一屏应该减少解释性文案，优先给用户直接记录和查看今天的能力。

## 3. 对小宝记的建议

### 3.1 主导航调整

当前有独立 `聊天` Tab。建议本轮改成：

1. 默认进入 `记录`。
2. 移除底部 `聊天` Tab。
3. 在记录页顶部或底部提供“记录输入条”：文字、语音、照片按钮仍保留，但语义变成“记一笔”，不是“打开聊天”。
4. AI 回复不再以完整聊天流长期占据页面，而是转成：
   - 已记好反馈卡；
   - 待确认卡；
   - 需要补充的信息卡；
   - 可折叠的“记录助手详情”。

推荐底部导航：

| Tab | 定位 |
| --- | --- |
| 记录 | 默认首页，承载今日记录、快速记录、时间线、成长数据、趋势入口 |
| 相册 | 宝宝照片/视频按天时间流 |
| 账本 | 暂时保留，不在本轮扩大或弱化 |
| 我的 | 宝宝资料、家庭成员、提醒管理、设置 |

### 3.2 记录页层级

记录页建议从“模块堆叠”改为“今天优先 + 回看分层”：

1. 顶部：宝宝名、年龄、日期切换、今天状态。
2. 第一屏：快速记录输入区。
   - 喂奶、睡眠、便便、体温、成长、更多。
   - 一句话/语音输入条：占位文案改为“记一笔今天的变化...”。
   - 图片入口仅作为记录素材或相册素材，不再强调 AI 聊天。
3. 今日摘要：轻量指标条。
   - 奶量/次数、睡眠、便便、最新成长数据。
   - 数据必须来自事件明细聚合，不得只显示最后一笔。
4. 今日时间线：按时间倒序或顺序展示事件。
   - 喂养、睡眠、便便、体温、成长、相册素材同日可联动。
   - 待确认记录放在时间线顶部，不藏在聊天气泡里。
5. 成长区：放在记录页内，但低于今日时间线。
   - 最新身高、体重、头围；
   - 添加/查看成长数据；
   - 发育里程碑入口；
   - 趋势入口。
6. 回看区：日历和趋势作为二级视图。
   - `今天`：默认；
   - `日历`：按日期找记录；
   - `趋势`：周/月统计、成长曲线。

### 3.3 聊天能力降级后的交互形态

聊天不是消失，而是变成记录页里的“输入和解释能力”：

- 用户输入“刚才喝了120ml母乳”，页面表现为记录动作。
- 成功后出现“已记好：喝奶 120ml 母乳，查看今天”。
- 信息不完整时出现“还差一点：母乳还是配方奶？”。
- 用户问普通问题时，可以在记录页内弹出轻量回复卡，但不再沉淀成一个主 Tab 聊天列表。
- 历史聊天消息仍可存储，但入口放进“我的 / 记录助手历史”或调试入口，不作为核心用户路径。

### 3.4 相册按天时间流

当前代码按月分组，相册 UI 名字叫 timeline 但实际 key 是 `YYYY-MM`。建议改成按天：

1. 分组 key 改为 `YYYY-MM-DD`。
2. 分组标题显示：
   - 今天 / 昨天 / 6月6日 周六；
   - 宝宝年龄，例如“出生第51天”；
   - 当天照片/视频数量。
3. 组内以时间倒序瀑布/网格展示。
4. 月份只作为快速跳转或粘性索引，不作为主分组。
5. 预览页保留编辑日期能力。
6. 日期来源优先级：
   - P0：`AlbumItem.occurredAt`；
   - 然后 `AlbumItem.date`；
   - 然后 `Attachment.createdAt`；
   - 最后上传时间。
7. P1 增加 `capturedAt` / `takenAt`：
   - 上传本地照片时读取 `File.lastModified` 作为弱拍摄时间；
   - 后续再解析 EXIF `DateTimeOriginal`；
   - 用户可手动改日期。

### 3.5 不建议本轮做的事

- 不做新的社区。
- 不做专家/知识付费。
- 不把 AI 架构调整塞进本轮。
- 不同时重构账本。
- 不在记录页加入太多知识内容或运营卡片。

### 3.6 AI 能力下放到模块

用户进一步确认后，本轮建议把 AI 从“独立聊天中心”调整为“各模块内的进阶能力”：

| 模块 | 基础能力 | AI/Pro 增强 |
| --- | --- | --- |
| 记录 | 手动维护喂奶、睡眠、便便、体温、成长测量、里程碑 | 文本/语音“记一笔”，生成已记好、待确认或需补充卡片 |
| 相册 | 上传照片/视频，按天时间流回看，编辑日期和备注 | P0 不强化 AI；P1 可考虑日期建议、精选封面、成长小故事、里程碑候选 |
| 账本 | 手动记账、分类、月度汇总 | Pro 图片/小票识别，生成待确认账本草稿 |
| 我的 | 宝宝资料、家庭成员、提醒管理、隐私、订阅 | 不放模型设置，不做 AI 功能中心 |

这样做的好处：

- 免费用户仍然有完整手动路径，产品不会因为 AI 失败而不可用。
- Pro 权益可以自然落到高成本、高价值能力上，例如图片/视频理解、小票识别、批量整理。
- 用户不需要理解“模型、模式、深度思考”，只在当前模块完成当前任务。
- 记录仍是主线，相册和账本各自保留清晰心智。

相册和 AI 的结合点本轮应克制。相册的第一价值是“按时间找回宝宝成长”，不是实时视觉问答。强行加入一个醒目的 AI 入口会让相册变复杂，也会拉高成本。更合适的后续方向是低打扰增强，例如自动建议照片日期、相似照片去重、精选封面、成长故事和里程碑候选。

## 4. P0 实施边界

建议 P0 只做可快速验证的产品结构调整：

1. 底部移除 `聊天` Tab，默认进入 `记录`。
2. 把聊天输入区抽成记录页的“记一笔”输入条。
3. 记录页第一屏重排为：日期/宝宝状态、快捷记录、今日摘要、待确认、今日时间线。
4. 成长数据和里程碑保留在记录页，但层级低于今日时间线。
5. 相册从按月分组改成按天分组。
6. 相册预览和编辑继续可用。

验收：

- 新用户登录后默认看到记录页。
- 底部没有聊天 Tab。
- 用户仍能从记录页用文字/语音/图片提交记录。
- AI/自动记录结果在记录页以卡片反馈，而不是要求用户进入聊天页查看。
- 相册同一天多张照片显示在同一个日期组；跨天照片显示为不同日期组。
- 相册组标题不再是“2026年6月”，而是具体日期。
