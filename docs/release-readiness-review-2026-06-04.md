# 小宝记正式发布上架评估与补齐 Spec

- 日期：2026-06-04
- 状态：发布前评估与补齐规格
- 结论级别：基于当前仓库、harness 证据和公开资料的产品/技术判断；不是法律意见，也不是压测报告。
- 产品边界：继续以“记录和陪伴”为主线；暂不做电商、专家/知识付费、开放社区。

## 1. 总结论

当前小宝记已经适合继续做小范围真实家庭内测，但不建议直接公开上架。

原因不是主线方向错了，而是“上架级基础设施”还没补齐：账号仍是手机号 + 家庭邀请码，没有真实短信验证码；用户信息和日志脱敏不足；Pro 目前是内测壳，权益、额度、支付和订阅恢复没有闭环；ECS 是单机 Spring Boot + SQLite + systemd，适合灰度验证，不适合无边界公开流量。

产品方向应保持不变：

> 免费层把记录做稳、做轻、做可信；Pro 只卖“更省心、更自动、更能整理”，不卖焦虑、不卖专家、不卖商品。

上架前的优先级应是：

1. 账号、安全、隐私、儿童信息和备案合规。
2. 免费/Pro 分层、用量额度、支付前置条件。
3. ECS 可观测、备份恢复、HTTPS/域名、媒体 OSS/CDN、压测。
4. 真实设备验证：通知、闹铃、ASR、媒体选择、OTA。
5. 产品体感收敛：低焦虑记录闭环、家庭共享边界、AI 非诊疗边界。

建议下一阶段不要新增大功能，先做一个 2 周发布硬化 sprint；完成后先走 TestFlight/国内安卓灰度/邀请码制，而不是公开投放。

## 3. 竞品路线与我们的取舍

### 国内常见路线

| 类型 | 代表 | 常见能力 | 对小宝记的启示 |
| --- | --- | --- | --- |
| 家庭相册 + 成长记录 | 亲宝宝 | 全家共享、照片视频云空间、成长记录、智能育儿、会员、商城 | 学“家庭共享、私密相册、长久保存、会员权益说明”；不学商城。 |
| 孕期育儿工具 + 社区 | 妈妈网孕育、宝宝树 | 孕期/育儿工具、成长记录、相册、社区、内容、专家、会员 | 学“工具覆盖、医学免责声明、App Store 订阅说明”；不做开放社区和专家内容。 |
| 专家 IP + 内容服务 | 育学园/崔玉涛类 | 权威医生 IP、知识内容、问诊/咨询、课程 | 我们没有资源，也会冲突信任边界，确定不做。 |
| 垂直公共健康工具 | 小豆苗类 | 疫苗、接种、科普、服务链接 | 可借鉴“事实提醒 + 权威来源 + 不替代医生”的边界表达。 |
| 纯记录工具 | 宝宝全记录、宝宝生活记录类 | 喂奶、睡眠、尿布、成长、健康、提醒、导出 | 基础记录必须可靠、快、可导出；但小宝记不应把核心记录做成强付费墙。 |

国内头部的共同点是：记录只是入口，商业化常转向内容、社区、专家、电商和会员。这个方向对大团队合理，但不适合小宝记现阶段。我们应该只学习它们的“上架成熟度”：账号、隐私政策、会员说明、客服入口、医学免责声明、权限说明、备案展示。

### 海外记录类路线

Huckleberry 和 Napper 更接近小宝记的产品形态：基础记录免费，高级洞察、AI logging、报告、预测、专家审核 AI chat 或计划放在 Plus/Premium。它们给我们的启发是：

- 核心记录不能被锁死，否则信任受损。
- 付费点应围绕“省心、洞察、自动整理、长期报告”。
- 睡眠预测很容易走向焦虑，小宝记不应把“预测正确”作为主战场。
- AI 付费不是模型炫技，而是减少输入、减少遗漏、减少整理负担。

### 我们的差异点

| 维度 | 竞品主流 | 小宝记应坚持 |
| --- | --- | --- |
| 主心智 | 内容/社区/专家/电商/相册 | 低摩擦记录 + 低焦虑陪伴 |
| AI | AI 管家、专家问答、预测 | 和真实 baby 数据绑定的中文陪伴与整理 |

## 5. P0 发布阻断项

这些是“公开上架前必须补”的事项。没有全部完成时，只建议邀请码内测。

### 5.1 账号、安全与隐私

#### P0-Auth-1：短信验证码登录

当前状态：

- `POST /api/auth/login` 接收 phone、inviteCode、roleName、caregiver。
- `AuthService` 当前注释明确第一版不接真实短信。
- 登录限流是内存 Map，适合单机内测，不适合多实例或正式风控。

规格：

- 新增发送验证码接口：`POST /api/auth/sms/send`。
- 新增验证码校验登录：`POST /api/auth/login` 增加 `smsCode`，或拆成 `POST /api/auth/sms/verify` 后签发登录 token。
- 验证码有效期建议 5 分钟；同手机号 60 秒内不可重复发送；同手机号/同 IP/同设备达到阈值后要求图形验证或冷却。
- 邀请码继续作为家庭加入凭证，但不能替代手机号真实性校验。
- 错误文案不能暴露“手机号是否已注册”的枚举信息。
- 所有短信 provider、模板 ID、签名、费用、失败码要进入配置与日志。

验收：

- 后端单测覆盖发送、过期、错误次数、重复发送、成功登录、旧邀请码兼容。
- 前端登录页覆盖验证码倒计时、错误提示、弱网重试。
- 云端 smoke 使用测试短信 provider 或 mock provider。

#### P0-Auth-2：手机号和用户信息脱敏

当前状态：

- `AuthUserDto` 返回完整手机号。
- `RequestLoggingFilter` 日志打印完整 phone。
- Pro 申请记录保存手机号。

规格：

- API 默认返回 `maskedPhone`，完整手机号只在必要接口和本人上下文使用。
- 日志统一脱敏为 `138****8990`，禁止完整手机号出现在 info/warn/error。
- 前端“我的”“成员”“登录识别身份”等展示脱敏手机号。
- Pro 申请、客服反馈、错误日志中的手机号应按最小必要原则保存。

验收：

- 单测或脚本扫描日志模板不再包含完整 phone。
- API JSON 断言默认无完整手机号。
- 前端 smoke 断言手机号展示为脱敏格式。

#### P0-Auth-3：Token 使用收敛

当前状态：

- `AuthTokenFilter` 支持 `Authorization: Bearer`，也支持 query 参数 `token`。

风险：

- query token 容易进入日志、浏览器历史、Referer 和第三方监控。

规格：

- 普通 API 禁止 query token。
- 上传、下载、WebSocket 如确需非 header 鉴权，改为一次性短期签名 URL 或连接后首帧鉴权。
- ASR 可以继续首帧传 token，但要加连接超时、未鉴权前不处理音频、错误码不泄漏细节。

验收：

- API 带 `?token=` 不再通过普通鉴权。
- 上传/缩略图读取使用签名 URL 或标准 Bearer。
- ASR 无 token/只读 token/过期 token 覆盖测试。

#### P0-Privacy-1：隐私政策、儿童信息规则、AI 使用说明

当前状态：

- `docs/commercialization/privacy-policy-draft.md` 是内测草案，明确不是正式法律文本。
- `DailySummaryView` 已有“观察来自记录，不替代医生”的说明。

规格：

- 正式隐私政策要列清：收集字段、目的、保存期限、家庭共享范围、账号私有范围、第三方服务、AI 模型处理、媒体存储、日志、删除/导出。
- 单独增加儿童个人信息保护规则：监护人同意、儿童信息范围、敏感信息、删除/更正方式、最小必要。
- App 内首登时展示隐私政策和用户协议勾选。
- 记录页/AI 入口提供“哪些数据会进入 AI”的短说明。
- 支持账号注销、家庭数据删除、媒体删除、数据导出申请。

验收：

- App 内可访问隐私政策、用户协议、儿童信息规则。
- 用户可发起注销/删除/导出，至少第一版进入人工工单。
- AI 调用前置说明覆盖文本、图片、视频。

#### P0-Compliance-1：备案与上架材料

规格：

- 完成 ICP/APP 备案；App 内和官网显著位置展示备案编号。
- 国内安卓渠道准备隐私合规自查：权限使用说明、SDK 清单、第三方共享清单、儿童信息说明。
- iOS 准备隐私营养标签、权限文案、订阅说明、账号删除入口。
- 如果接支付，准备会员服务协议、自动续费协议、取消/退款说明、客服方式。

验收：

- 上架包内权限声明与实际权限一致。
- 隐私政策中的第三方服务与代码/SDK/后端配置一致。
- 备案号和客服入口在 App/官网可见。

### 5.2 Free / Pro 与商业化

当前状态：

- 已有 `docs/commercialization/version-strategy.md`：Lite / Free / Pro 策略。
- 已有 `ProTrialController` 和申请/状态接口。
- `ProTrialService.isProEnabled()` 当前直接返回 true，说明正式权益没有启用。
- `AiUsageLogService` 能记录 usage，`AgentRequestGuard` 有家庭级限流和月 token budget。

#### P0-Pro-1：恢复真实权益判断

规格：

- `isProEnabled(familyId)` 改回 entitlement 判断。
- 明确哪些能力走 Pro：图片/视频 AI、周报/月报、高级趋势、更多 AI 配额、更多媒体空间。
- 明确哪些能力永远免费：基础记录、基础家庭共享、基础提醒、基础相册浏览、基础成长数据。
- Pro gating 只拦高级能力，不影响用户查看和导出已有数据。

验收：

- Free 家庭触发 Pro 能力时看到升级入口，不报技术错误。
- Pro 家庭可用高级能力。
- Pro 到期后高级新调用受限，历史数据仍可查看。

#### P0-Pro-2：额度和成本控制

规格：

- 建立家庭级额度：每日/每周图片、视频、AI 请求、token、报告生成次数。
- 明确超额文案：“本周试用额度已用完”，不静默失败。
- 后端 guard 使用持久化或 Redis，不依赖单机内存。
- usage log 要能按 family/user/feature/model/day 汇总成本。
- 管理员可手动调整白名单、额度和到期时间。

验收：

- 单测覆盖额度不足、额度恢复、Pro 到期、白名单调整。
- 前端展示剩余额度或至少展示用尽原因。
- 内测期间每周能导出家庭级成本表。

#### P0-Pro-3：支付前置条件

如果只是小范围内测，可以不接真实支付。如果公开收费，必须补：

- iOS 数字会员走 Apple In-App Purchase。
- 国内安卓渠道和私域支付单独评估，不在 iOS App 内引导绕过 IAP。
- 服务端校验 receipt / transaction，维护订阅状态、过期、取消、恢复购买。
- 支持 restore purchase。
- 订阅页清晰展示价格、周期、权益、试用、取消方式。
- 会员服务协议、自动续费协议和客服入口完整。

验收：

- 沙盒支付成功/失败/取消/恢复/过期全部可测。
- 订阅状态与后端 entitlement 一致。
- App Review 资料中权益、价格、协议链接齐全。

### 5.3 ECS、数据与访问量承载

当前状态：

- 部署脚本默认 ECS host `120.55.188.242`、后端端口 `8300`。
- systemd 启动单个 Java jar。
- 数据库存放在 `APP_DATA_DIR/baby-companion.sqlite`，SQLite WAL。
- 媒体默认本地存储，也支持 OSS。
- OTA 包通过 `/api/mobile-updates/check` 和 mobile-updates 目录/OSS 下发。

#### 当前承载判断

没有压测前，不能承诺具体 DAU/并发。基于当前架构，只能给出定性边界：

- 适合：5-10 家庭内测；几十个家庭的邀请码灰度；低并发真实使用。
- 勉强可控：低百级家庭、AI 调用有强额度、媒体走 OSS、请求有监控和备份。
- 不适合：公开上架后不限制注册、不限制 AI 和媒体上传、不做备份恢复、不做监控告警。

SQLite WAL 能支持多读和单写，但官方文档也明确同一时刻只有一个 writer。小宝记的写入很多：聊天消息、pending effects、care logs、album items、attachments、AI usage logs、agent traces。如果公开流量突然上来，瓶颈更可能先出现在写锁、媒体带宽、AI 队列和模型成本，而不是普通健康检查。

#### P0-Cloud-1：HTTPS、域名与备案

规格：

- 使用正式域名和 HTTPS。
- Nginx 或云负载均衡反代到 8300。
- CORS 只允许正式域名、localhost 开发域和 capacitor scheme。
- App 内 API base URL 不使用裸 IP。
- 官网/隐私页/协议页/备案号可访问。

验收：

- `https://domain/api/health` 可用。
- App 生产包只访问 HTTPS。
- HTTP 跳转 HTTPS。
- 备案号显示位置可见。

#### P0-Cloud-2：备份、恢复和数据保护

规格：

- SQLite 每日自动备份，保留 7/30/90 天策略。
- 媒体文件和 DB 备份分开；OSS 桶开启版本控制或生命周期策略。
- 每次部署前自动快照 DB。
- 每月至少一次恢复演练：新目录恢复 DB + 媒体 + 服务启动。
- 禁止默认 `SYNC_DATA=1` 覆盖生产数据，保持当前脚本的安全方向。

验收：

- 有可执行备份脚本和恢复脚本。
- 记录最近一次恢复演练时间、文件大小、耗时。
- 任意部署日志能看到是否备份成功。

#### P0-Cloud-3：可观测与告警

规格：

- 记录并脱敏：请求量、状态码、P95 latency、AI latency、上传失败、DB busy/locked、队列长度、token 成本、磁盘使用率。
- 告警：5xx、磁盘 > 80%、DB 备份失败、AI 成本超阈值、队列堆积、OTA manifest 下载失败。
- 增加 `/api/health` 之外的深度探针：DB 写读、移动更新 manifest、OSS 可用性、模型 key 配置状态。

验收：

- 内测每周可生成一页运行报告。
- 生产问题可以从 requestId 追到 Agent trace 和使用量。
- 日志无完整手机号和 token。

#### P0-Cloud-4：发布前压测目标

建议定义第一阶段公开灰度门槛，而不是拍脑袋承诺容量：

- 目标场景：100 个家庭、20 个并发用户、每分钟 30 次普通 API、每分钟 5 次 AI 请求、并发上传 3 个 20MB 文件。
- 普通 API：P95 < 800ms，不含 AI。
- AI 首 token 或首进度事件：P95 < 5s；最终回复按模型另计。
- 上传：失败率 < 1%，大文件有明确进度和失败重试。
- 数据库：无持续 `SQLITE_BUSY`，WAL 不异常膨胀。
- 系统：CPU、内存、磁盘、带宽均有余量。

验收：

- 压测报告记录命令、数据集、机器规格、结果、瓶颈和调参。
- 未达标时不能公开放量，只能邀请码灰度。

#### P1-Cloud：扩容路线

当真实家庭超过低百级或写入/媒体/AI 成本明显增长时，迁移方向：

- SQLite 迁移到托管 MySQL/PostgreSQL。
- Redis 承担验证码、session blacklist、限流、队列状态。
- 媒体统一 OSS + CDN，缩略图异步生成。
- Agent/视觉/日报生成进入异步任务队列。
- Spring Boot 可多实例部署，前面接负载均衡。
- 管理后台支持家庭/用户/额度/错误检索。

## 6. 产品设计补齐项

这些不是所有都阻断上架，但会影响真实留存和信任。

### P0-Product-1：首登和家庭边界说明

规格：

- 首登三步内让用户知道：哪些数据全家可见，哪些只自己可见。
- 家庭邀请码加入时展示当前家庭名和自己将加入的角色。
- 只读成员看到明确只读状态，不要误以为坏了。
- AI 入口提示“会读取哪些记录来整理，删除后的记录不会进入后续整理”。

验收：

- 新照护人、新只读成员、已有成员再登录各有 smoke。
- UI 文案不出现内部字段名。

### P0-Product-2：核心记录路径稳定性

规格：

- P0 功能必须形成稳定 E2E：登录、资料、聊天记录、记录页、成长数据、提醒、相册、账本、退出。
- AI 自动记录成功后必须显示“记录了什么、放在哪里、可撤销/可编辑”。
- 字段不足必须追问，不把猜测写入。
- 删除/修改历史数据必须经用户明确操作，不由聊天直接修改。

验收：

- `npm run verify:frontend` 覆盖移动视口。
- Agent benchmark 覆盖正向和边界。
- 至少一次云端测试账号 E2E，验证持久化和多账号共享。

### P0-Product-3：AI 安全和非诊疗

规格：

- 育儿建议只做科普和记录整理，所有医学/用药/高烧/呼吸/外伤/心理危机进入非诊疗边界。
- 情感陪伴可以承接疲惫、自责、焦虑，但不能诊断产后抑郁或提供治疗方案。
- 高风险语句必须建议联系家人、医生、急救或当地紧急服务。
- App Store 描述、隐私政策、AI 入口和回复文案口径一致。

验收：

- Agent benchmark 覆盖高风险输入。
- 人工抽样真实模型回复，不出现诊断、药物剂量承诺、替代医生。

### P1-Product：长期留存与导出

建议在公开上架后继续补：

- 一键复制/导出近 7/30 天儿保资料摘要。
- 家庭交接模板按爸爸/老人/月嫂不同阅读方式微调。
- 0-3 岁延展：辅食、过敏、发热用药事实记录、托育交接、语言动作里程碑。
- 月度小故事：照片 + 里程碑 + 照护事实，仍然低焦虑、不排名。

## 8. 30/60/90 天路线图

### 0-14 天：发布硬化，不新增大功能

目标：从“能跑”变成“可控内测”。

- 完成短信验证码方案和 mock provider。
- 手机号脱敏、日志脱敏、query token 收敛。
- 正式隐私政策/儿童信息规则/用户协议 v1。
- 恢复 Pro entitlement gating，保留手动白名单。
- 家庭级额度和超额文案落地。
- HTTPS 域名、备案准备、备份脚本、恢复演练。
- 云端测试账号 E2E：照护人/只读/多家庭/附件权限。
- 真机验证 Android/iOS 通知、ASR、媒体和 OTA。

### 15-45 天：灰度上架准备

目标：可以邀请 20-100 个家庭，不怕基本运营问题。

- App Store/TestFlight 与国内安卓渠道材料准备。
- 上架截图、描述、权限说明、隐私营养标签。
- 运行监控、AI 成本周报、错误告警。
- 压测并形成容量基线。
- OSS + CDN 或至少 OSS 全量媒体路径。
- Pro 会员页、内测申请和额度展示。
- 内测访谈闭环：误记录、误提醒、媒体慢、AI 不信任问题整改。

### 46-90 天：公开发布前架构升级

目标：决定是否公开放量和接真实支付。

- 若留存/付费意愿成立：接 IAP/安卓支付和订阅恢复。
- 若数据写入或媒体压力上升：启动 MySQL/PostgreSQL + Redis + 队列迁移。
- 增加管理后台：用户、家庭、额度、AI usage、错误查询。
- 数据导出/注销自助化。
- 近 7/30 天儿保资料摘要。
- 0-3 岁延展只做记录和陪伴，不扩成百科/课程。

## 9. 发布决策建议

### 可以做的发布

- 邀请码制内测。
- Android 小范围 APK/灰度渠道。
- iOS TestFlight 或开发者设备测试。
- Pro 手动白名单，不接真实支付。
- 明确告诉用户“内测阶段，可能存在不稳定，请不要把它当医疗工具”。

### 暂不建议做的发布

- 无限制公开注册。
- 公开收费订阅。
- 大规模买量。
- 开放社区。
- 专家咨询、课程、知识付费。
- 电商或商品推荐。

### 最推荐的下一步

开一个“发布硬化 Sprint”，只做 P0：

1. 账号安全：短信、脱敏、token 收敛。
2. 隐私合规：正式政策、儿童信息、删除/导出。
3. Pro 内测：真实 gating、额度、成本周报。
4. 云端：HTTPS、备份恢复、监控、压测。
5. 真机：通知、闹铃、ASR、媒体、OTA。

完成这些之前，产品方向不要再横向扩张。小宝记现在最需要的不是更多功能，而是让“记录和陪伴”这条主线足够可信、足够安全、足够稳定。
