## Why

小宝记当前已经具备照护记录、家庭共享、相册、提醒、账本和 Agent 能力，但商业化价值还不能只靠基础记录。基础照护日志在市场上较常见，直接对手动记录、基础提醒或基础家庭共享收费，容易伤害增长和信任。

本轮变更将 Pro 内测的第一付费锚点收敛为“少输入、少遗漏、自动整理”。目标不是马上接支付，而是在 `5-10` 个家庭中验证：用户是否愿意为更省心的 AI 自动整理能力付费，同时把服务器、OSS 和模型 API 成本控制在可观察、可告警的范围内。

## What Changes

- 新增 Pro 内测申请能力，申请极简化，只展示 Pro 能力说明并持久化申请记录。
- 新增家庭级 Pro 白名单权益，按家庭维度开通，所有家庭成员可见 Pro 状态。
- 新增 AI usage 明细记录，记录每次模型调用 token、provider、model、feature、input type、成功/失败和是否属于 Pro 能力。
- 新增今日小结能力：
  - 仅 Pro 白名单家庭可用。
  - 仅照护人可生成或重新生成。
  - 所有家庭成员可读。
  - 展示在记录 Tab 今日页。
  - 按家庭和日期持久化，保存最新一版，补录后可重新生成覆盖。
- 新增每日轻提醒：
  - 账号级开关和提醒时间。
  - 默认 `21:30`。
  - 只提醒用户确认生成，不自动调用模型。
- 新增漏项检查：
  - 第一阶段使用保守规则：绝对空缺、未完成事项、用户说了但未形成记录。
  - 关键漏项类型：喂养、睡眠、提醒/待办、待确认信息。
  - 文案使用“不确定、可忽略、可补充”的语气。
- 新增 Pro 内测入口：
  - 我的页。
  - 记录 Tab 今日小结区域。
  - 图片/视频 AI 理解触发处。
- 调整商业化文档成功标准：
  - 不再以“有兴趣”为准。
  - 要求明确愿意付费、说得出付费功能、实际使用过 Pro 能力。

## Capabilities

### New Capabilities

- `pro-trial-commercialization`: Pro 内测申请、家庭权益、AI usage、今日小结、漏项检查和轻提醒的产品与技术要求。

### Modified Capabilities

- `development-workflow`: 本变更会影响前端交互、后端状态、Agent 调用和移动通知，实施时必须遵循现有验证流程。

## Impact

- Backend:
  - 新增 SQLite 表：`pro_trial_application`、`pro_trial_entitlement`、`ai_usage_log`、`daily_summary`，以及可能的账号/家庭小结设置表。
  - 扩展 `/api/app/state` 或新增接口，支持 Pro 状态、申请、今日小结和设置。
  - Agent 调用链路需要记录 token usage，但第一阶段不向用户展示 token。
- Frontend:
  - 记录 Tab 今日页新增 Pro 今日小结区域和漏项卡片。
  - 我的页新增 Pro 内测入口和家庭 Pro 状态展示。
  - 图片/视频 Pro 能力触发处新增 Pro 内测入口或开通状态处理。
  - 设置每日小结提醒时间和接收开关。
- Mobile:
  - 每日轻提醒使用现有本地通知能力。
  - 提醒只引导用户确认生成小结，不自动后台生成。
- Agent / Cost:
  - 记录每次模型调用 token 明细。
  - 第一阶段只做后台软告警，预留硬限制，不给用户展示 token。
- Data / Privacy:
  - 今日小结家庭共享，但生成时只使用家庭共享数据。
  - 不读取账号私有聊天、私有提醒、私有待确认、私有记忆或会话摘要。

## Non-Goals

- 不接真实支付。
- 不实现正式会员系统。
- 不做后台管理页。
- 不向用户展示 token 或模型技术字段。
- 不做 Lite 纯客户端版。
- 不做复杂智能历史规律漏项判断。
- 不自动生成小结消耗模型成本。
- 不做周报/月报完整体系，只保留后续扩展设计。
